    Changelog¶

    All notable changes to Ferry. Versions follow Semantic Versioning; while Ferry is pre-1.0, minor versions may contain breaking changes.

    0.10.0-beta.2¶

    Fixes¶

    • Send with the published version no longer fails with HTTP 500 on an unpublished page. A page that was published and then unpublished keeps an old published version id in Umbraco but has no published name, and the export sent a null name. Ferry now treats such a page, and a page never published, as having no published version.
    • Sending a tree (for example Send everything) with the published version leaves out the pages that have no published version, and the review names them ("N pages were left out because they have no published version: …"). A page selected on its own without one is refused by name and key; a published page below a left-out one fails, naming both. The full-site export names the pages it leaves out the same way.
    • A page with no name to send is reported by name and key instead of failing the export.
    • A transferred relation type is found on the receiving site straight away. Its relation type and relations were stored, but Umbraco's cached set of relation types still predated the apply, so they were not found until the site restarted.
    • The note naming left-out pages is shown to administrators only: a delegated editor's selection can reach pages outside their grant.

    Testing¶

    • Each release is checked against the packed packages by every end-to-end suite and the browser tests, and by a check that every Ferry endpoint was called successfully.

    0.10.0-beta.1¶

    Features¶

    • Atomic apply (Full adapter). Each apply batch (one push batch, one Pull, one package import or one restore) runs in one Umbraco scope on the receiving site, media and view files included. The DraftText adapter is unchanged: it writes item by item. A cancelling Saving/Publishing/Moving handler, failed validation or any error rolls the whole batch back; the result says nothing was kept. Saved and Published handlers run once per batch, after the commit. If one throws, the batch stays saved and is reported Completed with a warning, and Ferry refreshes the cache and search index for the batch.
    • Handler messages. The message a handler on the other site gave when it cancelled a save, publish or media save reaches the apply and publication results, operation history and the backoffice.
    • Large-apply warning. A Pull, package import or restore above Ferry:Backoffice:LargeApplyWarningItems (default 1,000 written items; Unchanged and schema items do not count) says that it applies in one transaction and that editors on the site cannot save while it runs; the review asks for confirmation. The apply is never refused on size.

    Fixes¶

    • Document-type inheritance is kept on the target: an inherited type is no longer placed in folders named after its parents, and Inheritance no longer becomes Composition (F1).
    • Document-type folders keep their keys across sites (F2).
    • New content and media are created with their values in the first save, so a handler that checks required values accepts them; the source sort order is kept (H1-c).

    Upgrade notes¶

    • Upgrade both sites. Until both run this version, inherited document types in folders show Update on every transfer.
    • Site Saved/Published handlers now see a batch at once, after the whole batch is saved, instead of one item at a time between Ferry's writes.
    • A long Pull, package import or restore blocks backoffice editors on that site while it runs: on SQL Server their saves fail after Umbraco's 5 s lock timeout.

    0.9.0-beta.1¶

    Features¶

    • Redesigned Sites page in Settings › Ferry. This site shows the site's name, address and role (Development, Staging, Live or Other); Ferry:Backoffice:SiteRole fixes the role in configuration (Set in configuration), and configured destinations can declare Ferry:Backoffice:Destinations:<id>:Role.
    • Connected sites table. One row per site, joining our connection and their access key: role badge, address, what we may and they may do (Send, Get, Publish, Compare), and status (online, unreachable with the reason, not checked, Check again). Edit changes name, role, Get and their permissions and has separate Revoke their access and Stop connecting; Disconnect does both. A site managed in configuration can only have their key revoked here. Saving unchanged permissions leaves the key (and approvals bound to it) untouched.
    • Connect a site validates the pasted pairing code as you paste (site, what it allows, two-way, hours left, or why it cannot be used), lets you set the new site's role, and for two-way codes choose what the other site may do and edit this site's address. No pairing code? keeps the address and key fallback, now with a role too.
    • Let another site connect. Create a pairing code with permission chips and two-way wishes; it is shown once with Copy. The codes table shows Waiting (hours left), Used by and Expired, with Revoke or Remove.
    • Compare permission. A new read-only peer permission for item inventories, implied by Send or Get on access keys and by Preview or Export on configured peers. Nothing uses it yet; the compare view comes in a later release. Policy hashes are unchanged, so existing approvals and durable jobs stay valid.
    • Site tests also report whether the other site lets this site publish.
    • Connecting (by pairing code or address and key) to a site that is already a configured destination is refused with a message, so the Sites page never shows one site twice; a pairing code is not used up by the refusal.

    Changes¶

    • The separate Access keys and Pairing codes not used yet lists are gone. Every access key now appears as a row in Connected sites: edit its permissions there and revoke it with Disconnect.
    • The pairing-code list API now also returns used and expired codes, kept for 30 days.

    0.8.0-beta.1¶

    Features¶

    • Redesigned transfer panel for Send, Get and the queue: Choose (site cards, what to send, version, language chips and option switches with help), Review (summary tiles, always-visible notes and warnings, schema changes as a change table) and Done (links to the items, Undo this get after a Get). Loading placeholders, progress for large sends, Try again after an error and an empty state when no site is connected. The queue offers the same version and language choices (when it holds pages) and the same option switches as a single transfer.

    0.7.0-beta.4¶

    Fixes¶

    • Publish after sending counts only published pages as already up to date: "Sent 1 changed item and published 4 pages (3 already up to date) on Target." Before, the unchanged count included every dependency in the review.

    0.7.0-beta.3¶

    Fixes¶

    • Paired sites are no longer all named "Ferry". Pairing codes and claims name this site with the new optional Ferry:Backoffice:SiteName, otherwise its host (e.g. staging.example.com, localhost:49191), set by the server instead of the browser page title.
    • Review notes use the singular for one note ("1 note — it does not block sending").
    • Unresolved-reference notes name the item that links to the missing one, and shorten the missing item's key: "Unresolved reference to Media 279fdd7b… in Content “Home”: …".
    • Publish after sending says what was sent and what was published: "Sent 1 changed item (3 unchanged) and published 4 pages on Target", with singulars.
    • The Connect a site wizard shows its first step as one sentence instead of one line per fragment.

    0.7.0-beta.2¶

    Features¶

    • Send or get a whole tree. Administrators get Send everything to… and Get everything from… on the Content and Media section roots. Each opens the usual transfer panel with every top-level item and its descendants selected; Content brings its dependencies and referenced media, Media sends only the media library. Large sends split into batches as before.
    • Publish after sending. Content sends (single items, the queue and whole-tree sends) offer Publish on after sending to administrators when the destination supports publication. After the send, Ferry reviews and publishes the selected items and their child items (not dependencies) in the sent cultures, and reports "Sent N items and published M on ". A publication review with errors is not forced: the drafts stay and the review opens. Not available for background sends. Preview operations now carry their parent key, and GET connections/{id}/publication-support tells administrators whether a destination can publish.

    Changed¶

    • Pairing codes work once and can connect both ways. A pairing code (ferry2.…) is now a one-time invitation that expires after 24 hours, not the access key itself. The site that pastes it redeems it at the new POST /ferry/v1/pairing/claim; the issuing site then creates a new access key and records which site used it. A second use says "This pairing code was already used. Create a new one." With Allow two-way, the other site's admin can grant access back in the same step, and both connections are saved. ferry1.… codes are refused (breaking).
    • The Sites tab lists unused pairing codes with their expiry, and access keys with the site that used them; both can be revoked. Create an access key instead still issues a plain key for connecting by address.
    • POST access-keys no longer returns a pairing code; pairing uses the new pairing-codes and servers/pair management endpoints. Existing access keys and connections keep working.

    Fixes¶

    • The add-to-queue message says "1 item is queued" instead of "1 items are queued" (English and Spanish).
    • Get shows its notes. The Get (pull) and package-import reviews now list the same notes as Send, such as a page pointing at media that is not in the transfer. Before, a Get silently left such references unresolved.
    • Clearer unresolved-reference note. It now says that an item deleted or in the source's recycle bin must be restored there and sent again, and that saving the page before it arrives removes the link.
    • Export failures say why. When the source cannot export a selection, the destination now shows the source's reason instead of a bare "400 (Bad Request)".

    0.7.0-beta.1¶

    Breaking¶

    • Every remaining pre-Ferry name is now a Ferry name, with no compatibility: routes /ferry/v1/…, headers X-Ferry-*, tables cmsFerry*, permissions Ferry.Push / Ferry.Pull, packages .ferry.zip, pairing codes ferry1.…, configuration only under Ferry, and no legacy file imports. Both sites must run the same version; existing Ferry data starts fresh.

    0.6.0-beta.2¶

    Security¶

    • Umbraco Forms file settings. Forms transfers refuse a view path outside the Forms email template folder (Forms/Emails/), and a Save as an XML file workflow whose Extension is not xml, txt or csv. Before, any relative .cshtml path and any extension that did not look like a server file were accepted (behaviour change).
    • Managed server access keys. Changing a managed server's address (scheme, host or port) now requires entering its access key again, so a stored key is never sent to a different host. Saving the same address keeps the stored key.
    • Redirect conflicts. The Skybrud redirects conflict error no longer includes the receiving site's own redirect key, which a peer with only Preview permission could read.

    0.6.0-beta.1¶

    Schema as generated C# migrations¶

    • Generated migrations. With Ferry:Schema:Migrations enabled on a development site, schema edits in the backoffice keep a draft migration (_PendingSchemaChanges.cs, never compiled) up to date, and Create migration (Settings › Ferry › Advanced, or POST /umbraco/management/api/v1/ferry/schema/migrations) turns it into a timestamped SchemaBuilder migration and adds it to the generated plan file FerrySchemaPlan.g.cs. The first one adopts the site's whole schema; later ones contain only what changed. See generated migrations.
    • Per-environment history. Every environment runs the listed migrations it has not run yet, in step id order, at startup. A failing migration is rolled back, blocks the later ones, and is shown on the Advanced tab and by the new Ferry schema migrations health check; the site keeps running and the next start retries it.
    • Drift. Schema changed outside the migrations (for example directly on live) is listed on the Advanced tab and by the health check until it is resolved, across deploys: a migration that changes a drifted item does not hide it. Administrators can Accept current schema (Advanced tab, or POST …/ferry/schema/migrations/accept, all items or selected keys) to take the schema as it is there.
    • Create migration refuses while the plan lists migrations the database has not run, so a teammate's change is never undone by a diff against a database without it.
    • New SchemaBuilder steps: Remove…Async for every schema kind and for properties, groups, tabs and compositions; Rename…Async for document types, media types, templates, properties, groups and tabs; MovePropertyAsync. Removals refuse when stored values exist unless you pass allowDataLoss: true by hand.
    • .Folder(...) in Ensure… now moves an existing item into the stated folder (.Folder("") = root).
    • Files are written only in the Development environment, outside Umbraco's Production runtime mode, inside ProjectPath. Member types are not covered.
    • Sites with a hand-written 0.5 schema plan keep it running; to switch, create a first (adoption) migration and remove the old plan registration in the same commit.

    Breaking¶

    • SchemaCodeExport is created through dependency injection only; its constructor is now internal. Resolve it, or ISyncSchemaCodeExport, from the container.
    • SchemaBuilder and UmbracoFullSyncStore have new optional constructor parameters. Source that calls them compiles unchanged, but code compiled against 0.5 that constructs them directly must be rebuilt (binary break).

    Behaviour changes¶

    • EnsureDataTypeAsync with a stated key adopts an unused data type of the same name (re-keying it), as transfers do, instead of refusing; a namesake in use is still refused.
    • A template whose view's Layout names a plain view rather than a template is created without a master template (in SchemaBuilder and transfers), instead of failing with MasterTemplateNotFound.
    • Pages and media that no longer fit their type's root or child rules are copied where the source has them also when their type is unchanged on the destination; for media, the root and child rules are relaxed the same way as for content.
    • .Folder(...) in Ensure… moves an existing item into the stated folder; before, it applied only to new items.
    • UmbracoMediaTransfer.ValidateAsync has a new overload taking the unchanged schema items; the 0.5 overload is kept.

    0.5.0-beta.1¶

    Self-contained¶

    • Self-contained. Ferry no longer depends on any other synchronisation package. Schema is written and read by Ferry's own serializer and importer on Umbraco's services, and property values by Ferry's own value mappers, built on Umbraco's reference tracking. Sites that also run another synchronisation tool keep working side by side.
    • Value mapper API: IFerryValueMapper and AddFerryValueMapper<T>() let you add support for your own property editors; see extending Ferry.
    • Language keys are derived from the ISO code, and built-in member property keys from the member type and alias, so every site agrees on them.
    • Transfer formats are now Full v7 / v8. Upgrade both sites together: 0.4 and 0.5 sites refuse to exchange transfers or packages with each other.

    0.4.0-beta.1 — first public release¶

    License and distribution¶

    • Ferry is now free to use and closed source, under the Ferry Freeware License: free for any site, including commercial work; no redistribution, modification or reverse engineering. Earlier builds were never published.
    • Packages ship obfuscated, without source, symbols or repository links.

    Package data in transfers¶

    • Package providers: a package can add data it keeps outside content (redirects, forms, …) to Ferry transfers by implementing IFerryPackageProvider. Items keep their keys, show in the review with their changed fields, and are written after the pages and media they point at. Off by default: set Ferry:Full:AllowPackageItemTransfer on both sites. A site without the provider refuses those items before anything is written. See extending Ferry.
    • Ferry.Skybrud.Redirects carries Skybrud redirects. Destination URLs must be site paths or http(s) URLs.
    • Ferry.Umbraco.Forms carries Umbraco Forms definitions with their workflows, and accepts the form and theme pickers. Workflow view paths must stay inside the site's views, and address settings must be public http(s) URLs.
    • Ferry:Full:AdditionalMediaExtensions allows a site's own static media types (for example .pdn). Types a browser or the server can run are refused.

    Fixes¶

    • Templates whose Layout is a plain view rather than a template transfer, including over an existing view file.
    • Pages that no longer fit their type's root or child rules copy as the source has them when the type comes along.
    • Blueprints kept in a blueprint folder no longer stop a whole-site export.
    • The display-only Umbraco.ListView property of upgraded sites is accepted.
    • Legacy {localLink:umb://…} links in rich text inside blocks no longer block the import.
    • On SQLite, Ferry's lease renewal no longer commits in the middle of an entity write, where Umbraco's relation tracking would fail with "database is locked" after retrying for minutes.
    • Legacy {localLink:1234} links by integer id approve the page they resolve to, so the import no longer refuses them as unapproved references.
    • A page whose type varies by culture but that exists in no language is left out of a whole-site export with a warning, instead of stopping it.
    • Changing a data type's editor or storage, or changing or removing a property, is allowed when no stored value uses it (a fresh site's built-in types). Element types always count as used, since block values are stored in pages.
    • Block values written in another order compare equal.
    • A peer request refused with 422 is logged with its cause on the refusing site.
    • The "would lose or change data" message shows both values as text where they differ.

    0.3.0-alpha.1 — 2026-10-24¶

    Code-first schema¶

    • SchemaBuilder covers the whole schema (#30):
    • data types, with their portable configuration;
    • templates (the view file ships with the site; the layout comes from its Layout);
    • languages, media types and custom relation types;
    • document types with tabs and nested groups, folders, allowed and default templates, list views, variations, history cleanup and every property setting. Definitions are written through the same serializers transfers use, so a migration produces exactly the schema a content-only transfer compares. Nothing is removed, and destructive changes are refused.
    • Adopt code-first on an existing site (#30, #33):
    • Settings › Ferry › Advanced › Download schema as code, or GET ferry/schema/code, writes the site's schema as one migration that keeps every key.
    • The download is a zip with one partial-class file per schema kind; format=cs returns a single file.

    Backoffice¶

    • Spanish translation (#31). Every term the backoffice uses now has English and Spanish text, including the workspace tab labels.
    • The Danger zone heading contrast is fixed in the light and dark themes (#31).
    • Queue changes survive a reload (#32): clearing the queue and reloading at once no longer brings items back.

    Fixes¶

    • Get fixes (#29):
    • non-root pages kept their templates;
    • template layouts come from the Razor Layout;
    • .jfif, .jpe, .heic and .heif media are allowed;
    • orphan segment values are skipped;
    • FerryImport.IsActive lets site handlers skip work during an apply;
    • legacy block UDIs, SQL Server and SQLite dates, empty values and empty rich-text blocks no longer plan as updates.
    • Items Umbraco renamed "Name (n)" because a destination sibling holds the source name plan as unchanged (#32).
    • The packaged dashboard no longer imports a chunk that was not committed (#31).
    • SQLite: a durable apply could stall for minutes while its restore point was saved. Ferry's database work read and then wrote in one deferred transaction; when another request committed in between, SQLite refused the write (SQLITE_BUSY_SNAPSHOT), which waiting never fixes, and the provider kept retrying it. Ferry's write work now takes SQLite's write lock first, as Umbraco does.
    • The README now recommends SQL Server for production sites that receive transfers, or SQLite with Cache=Private (#32).

    0.2.0-alpha.1 — 2026-10-23¶

    Renamed and standalone¶

    • Ferry name (#19). Packages are Ferry.Core, Ferry.Transport, Ferry.Umbraco and Ferry.Backoffice; configuration lives under Ferry.
    • Standalone package (#20). Ferry has its own workspace under Settings › Synchronisation and needs no other synchronisation package.

    Backoffice redesign¶

    • Send and Get replace Push and Pull throughout the interface (#21).
    • Pickers instead of GUID fields, with a key fallback for items that exist only on the other site (#21).
    • Review screen leads with a summary ("4 new pages"), calls out schema changes, moves and templates, and keeps the full list and unchanged items behind toggles (#22); the Publish review follows the same layout (#27).
    • Overview, Sites, Packages and Advanced tabs (#23): connected-site diagram, whole-site Send and Get, activity in plain sentences, a Connect a site wizard with pairing codes, drag-and-drop package import, and a danger zone for recycle-bin moves and seeding.
    • Top-bar Ferry panel with Queue and Activity tabs, and an Add to queue action (#23).
    • Side-panel buttons sit in the panel footer (#24); compact site cards, a single Synchronisation heading, and theme-aware colours (#25); Umbraco form controls, first-run guidance, a Managed in config badge and visible keyboard focus (#27).
    • Settings-tab text is translatable through ferry_* keys (#26, #27).
    • Connection checks on the Sites tab are cached for five minutes (#26).

    Features¶

    • Editors see their own activity: GET ferry/operations/mine (#26).
    • Code-first schema: SchemaBuilder with stable, alias-derived keys (#18).
    • Content-only sites: Ferry:Full:ContentOnly rejects transfers that would change schema (#17).
    • Granular permissions on top of delegated grants (#16) and a server-side per-user transfer queue (#14).
    • Package import at startup (#12), a cluster operation lease (#11) and bulk-apply suspensions (#9).

    Fixes and maintenance¶

    • Audited transitive package versions (#10) and editor reference coverage (#13).
    • The Settings workspace source is TypeScript.

    0.1.0-alpha.1¶

    First experimental release: reviewed Full-mode Push and Pull, packages, snapshots, publication, delegated editors and the native backoffice dashboard. No package was published.
